# baseball-record-analyzer

수기 야구기록지(스코어북) 스캔본을 구조화 데이터로 옮기고, **기록지 양식 그대로** 화면에서
확인·수정·입력할 수 있는 웹 편집기.

가운데 볼카운트(타석 다이아몬드) 영역은 **A시트 1~4회(5·7·14·8타석)까지 판독**해 화면에 표시합니다.
나머지 칸은 아직 빈 칸이고, 원본에서 읽기 어려운 표시는 채우지 않고 칸의 `note` 에 사유만 남깁니다.

## 폴더 구조

```
data/records/        원본 스캔 이미지 (20230402-A.jpg, 20230402-B.jpg)
data/parsed/         이미지에서 읽어낸 구조화 데이터 (시트당 JSON 1개)
data/innings/        볼카운트 영역을 이닝별로 잘라낸 이미지 (자동 생성)
tools/build_records.py     data/parsed/*.json → web/records.js 번들
tools/extract_innings.py   스캔본 → 이닝별 볼카운트 이미지 + manifest.json
web/                 기록지 웹 화면 (index.html / style.css / app.js / records.js)
docs/                기록방법·파이프라인 참고 문서
```

## 실행

```bash
# 방법 1 — 파일을 그대로 연다 (별도 서버 불필요)
open web/index.html

# 방법 2 — 로컬 서버
python3 -m http.server 8777
#  → http://localhost:8777/web/index.html
#  → http://localhost:8777/web/index.html?sheet=20230402-B
```

`data/parsed/*.json` 을 고쳤다면 번들을 다시 만듭니다.

```bash
python3 tools/build_records.py
```

## 볼카운트 영역 이닝별 잘라내기

```bash
python3 tools/extract_innings.py            # data/records/*.jpg 전부
python3 tools/extract_innings.py 20230402-A # 시트 하나만
```

기록지 가운데의 볼카운트(타석 다이아몬드) 영역은 **9행(타순 1~9) × 14열** 격자이고,
한 열은 `볼/스트라이크 스트립(약 47px) + 다이아몬드(약 173px)` 로 나뉩니다.
칸이 채워지는 순서는 **이닝 단위가 아니라 타순 단위**입니다.

- 한 이닝은 그 이닝 선두타자의 행에서 시작해 아래로 내려가고, 9번 다음은 **같은 열의 1번**으로 돌아옵니다.
- 타순이 한 바퀴를 다 돌면(9칸) 같은 이닝이 **다음 열로 이어집니다.** (A시트 3회 = 3열 9타석 + 4열 5타석)
- 이닝이 끝나면 다음 칸에 빨간 사선을 긋고, 다음 이닝은 **다음 열의 같은 타순 행**에서 시작합니다.

`extract_innings.py` 는 인쇄된 파란 괘선으로 격자를 검출하고, 칸별 연필 잉크량으로 타석 사용 여부를
판정한 뒤 위 규칙대로 걸어서 이닝을 나눕니다. 아웃카운트를 읽지 않아도 **빈 칸이 이닝의 끝**입니다.

산출물 (`data/innings/<시트>/`)

| 파일 | 내용 |
| --- | --- |
| `inning-N.png` | 그 이닝이 걸친 열 전체. 해당 이닝 칸만 선명하게, 타석 순번을 번호로 표시 |
| `inning-N-seq.png` | 그 이닝의 칸만 **타석 순서대로** 가로로 이어 붙인 띠 (판독용) |
| `cells/iN-paM-slotR.png` | 칸 하나짜리 이미지 |
| `manifest.json` | 격자 좌표, 이닝→(타순, 열) 매핑, 칸별 연필/빨강 잉크량 |

실행하면 `data/parsed/*.json` 의 투수표·라인스코어와 대조한 검증표가 함께 출력됩니다.
두 시트 모두 **판독한 칸 수 = 투수표 타자수** 이고(A 41, B 34), 이닝별 잔루도 음수가 나오지 않습니다.

| 키 | 내용 |
| --- | --- |
| `form` | `top`(초공격 양식) / `bottom`(말공격 양식) — 상·하단 박스 구성이 달라짐 |
| `header` | No., 날짜, V/H 팀, 관중수, (B) 구장·온도·습도·일기·풍속 |
| `linescore` | 이닝별 득점표 2행 |
| `slots[10].rows[3]` | 타순 1~9 + 교대란 행. 행마다 등번호·풋아웃·어시스트·실책·병살·수비위치·선수명·비고·`bat`(18개 타격 집계) |
| `subs` | 교대란 메모 |
| `totals.hits / fielding / pitches` | 이닝별 하단 집계. 이닝마다 `{l: 좌측칸, r: 우측칸}` |
| `gameInfo` / `umpires` / `agreement` / `suspension` | (A) 시간·심판·합의판정·경기중단 |
| `homers` / `doublePlays` / `passedBall` / `indifference` / `remarks` | (B) 홈런타자·병살내용·패스트볼·무관심진루자·비고 |
| `pitchers` | 투수 기록표 (승패, 이닝 `ipWhole`+`ipThird`/3, 타자, 투구수, 타수, 피안타 …) |
| `diamond` | 볼카운트(타석 다이아몬드) 판독값. 칸 하나 = 배열 원소 1개 |
| `notes` | 판독 시 애매했던 지점 메모. 화면 아래에 표시됨 |

### `diamond` 원소

칸의 자리는 **이닝이 아니라 `(slot, col)`** 입니다. 한 이닝이 두 열에 걸치기 때문입니다.

```json
{ "slot": 1, "col": 1, "inning": 1, "pa": 1,
  "count": ["B","B","B","S","B"],
  "z": { "a": "B", "b": "S2", "c": "", "d": "" },
  "center": "ℓ", "kind": "lob", "result": "",
  "note": "2루→3루 칸에 숫자로 보이는 표시가 있으나 판독 불가" }
```

| 키 | 내용 |
| --- | --- |
| `count` | 볼카운트란(칸 왼쪽 좁은 띠)의 투구 기호를 던진 순서대로. 못 읽으면 빈 배열 |
| `z` | 다이아몬드 네 귀퉁이 — `a`=홈\~1루, `b`=1\~2루, `c`=2\~3루, `d`=3루\~홈 |
| `center` | 다이아몬드 한가운데 — `I`/`II`/`III`(아웃카운트), `ℓ`(잔루), `⊘`(자책 득점), `○`(비자책 득점) |
| `kind` | `out` / `lob` / `run` — 화면 표시 색을 정한다(잔루는 원본처럼 빨강) |
| `result` | 다이아몬드 아래 타격 결과 코드 (`F8`, `K`, `6-3` …) |

`count` 기호 코드 (출처: `docs/2023recordRaw_스코어북 기록방법.pdf`)

| 코드 | 기호 | 뜻 | | 코드 | 기호 | 뜻 |
| --- | --- | --- | --- | --- | --- | --- |
| `B` | `＼` | 볼 | | `F` | `△` | 파울 타구 |
| `S` | `Ɔ` | 그대로 보낸 스트라이크 | | `BF` | `▲` | 번트 파울 타구 |
| `W` | `⊖` | 헛친 스트라이크(파울팁 포함) | | `BM` | `●` | 번트 헛스윙 |
| `H` | `θ` | 타격완료 | | `X` | `×` | 자동고의4구 시점 |

`result` / `z` 에 쓰는 결과 코드도 같은 문서를 따릅니다 — `/9` 우익수 앞 안타(안타는 `/`+야수번호),
`F8` 중견수 플라이 아웃, `K` 삼진, `4-3` 2루수 땅볼 1루 송구 아웃, `E5-3` 3루수 송구실책으로 출루,
`B` 볼넷, `IB` 고의4구, `HP` 사구, `1-3`/`5-3` 야수 송구 아웃,
`S`+타순 도루(그 타순 타석 때 훔침), `BK`+타순 보크 진루.

**동그라미 친 한자 숫자 `(一)`~`(九)` 는 그 진루를 만든 타자의 타순입니다.** 기록방법 문서의
야수선택 예시에 1번타자 칸의 1루~2루 자리에 `(二)` 가 있고 본문이 *"1루주자는 2번타자의 타구에
의한 도움으로 2루까지 진루"* 라고 설명합니다. 그래서 한 주자의 네 귀퉁이를 왼쪽 아래부터 읽으면
타순이 순서대로 올라갑니다 — A시트 3회 김재관 칸이 `(二)(三)(四)`, 정진용 칸이 `(三)(四)(五)` 입니다.

`totals` 의 `l`/`r` 은 기록지에서 이닝 칸이 좌·우 두 칸으로 나뉘어 있는 구조를 그대로 옮긴 것입니다.
읽어보면 **안타 행 = 좌: 안타(이닝/누계), 우: 득점**, **투구수 행 = 좌: 이닝 투구수, 우: 누계** 로
쓰여 있습니다(투구수는 두 시트 모두 누계가 정확히 맞아떨어져 확인됨).

## 판독 정확도에 대해

숫자 집계는 기록지에서 `一 / 丁 / 下 / (4획) / 正` 형태의 획수 탤리로 적혀 있어, 획을 세어
숫자로 옮겼습니다. 아래 항목은 원본 필체가 애매해 **확인이 필요**하며 화면에서 바로 고칠 수 있습니다.

- 좌측 수비기록(풋아웃/어시스트/실책/병살): 숫자가 칸 경계에 걸쳐 있어 어느 칸의 값인지 불확실
- ~~A시트 하단 집계행: 기록자의 칸 밀림~~ → **밀림이 아니라 규칙입니다.** A시트 3회는 타석이 14개라
  3열을 다 쓰고 4열로 이어졌고, 기록자는 **이닝이 끝난 열**에 그 이닝의 집계를 적었습니다.
  그래서 3열 집계가 비고 4·5·6열에 3·4·5회 집계가 들어갑니다. 기록지 상단에도 인쇄된 이닝번호
  5·6을 지우고 4·5로 고쳐 적어 두었고(3열↔4열 사이에는 `⇒` 표시), 열 위 여백의 누계
  `3 / 9 / 15 / 20 / 26` 은 이닝별 **타수** 누계로 투수표 타수 합 26과 맞아떨어집니다.
  `data/parsed/20230402-A.json` 의 `notes` 에는 아직 옛 설명이 남아 있습니다
- B시트 온도 `46`, 1번 타자/교체선수 이름 첫 글자(서/설, 설/심)
